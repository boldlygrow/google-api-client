# 5.0

* **Release Date:** 2026-09-07

## Overview

This release moves the project to the maintainer's `BoldlyGrow` namespace, replaces the deprecated `provisionesta/audit` dependency with `boldlygrow/audit-log`, extends framework support to Laravel v13, and drops support for the legacy Laravel v8, v9, and v10 releases. The API surface, authentication (service account with OAuth 2.0 JWT bearer tokens and per-call scopes), and response formatting are unchanged, so existing calls continue to work after the namespace and dependency updates below.

### New Features

- Add Laravel v13.x support
- Add [Laravel Pint](https://laravel.com/docs/pint) and [Pest](https://pestphp.com/) as development dependencies for linting and testing
- Add docblocks to the published config file documenting each configuration key
- **Error messages**
    - Exception messages now include the reason that the Google API returned for the failure, and use the format `METHOD CODE URL (Reason) <status> <message> (Details) <field violations>`.
    - `error.details[].fieldViolations[]` and `error.errors[].reason` are now appended, so a response whose top level `message` is the generic `Request contains an invalid argument.` now names the fields that were rejected (ex. `(Details) parent: Invalid parent, user.name: Must not be empty`).
    - The `error` and `error_description` keys returned by the OAuth 2.0 token endpoints are now read as well. These responses previously produced a message with only the method, status code, and URL.
    - If the response body uses none of these keys, the body is appended (truncated to 1000 characters) instead of being discarded.
    - The audit log `errors.message` value now contains the same parsed reason.
    - A decoded copy of the URL is appended to the message when it differs from the URL that was requested (ex. a `query` query string). The encoded URL is still shown first and is the one that reproduces the request.

### What's Changed

- **Package Architecture**
    - The Composer package has been renamed from `provisionesta/google-api-client` to `boldlygrow/google-api-client`.
        - **Why:** The project is consolidating under the maintainer's `BoldlyGrow` organization alongside the related audit and actions packages.
    - The PHP namespace changed from `Provisionesta\Google` to `BoldlyGrow\Google`.
    - The `glamstack/google-api-client` and `provisionesta/google-api-client` package names are retained as `replace` aliases for a smoother upgrade.
- **Audit Logging**
    - The audit logging dependency changed from `provisionesta/audit` to `boldlygrow/audit-log`.
        - **Why:** `provisionesta/audit` is deprecated. `boldlygrow/audit-log` is its direct replacement under the maintainer's organization.
    - The imported class changed from `Provisionesta\Audit\Log` to `BoldlyGrow\AuditLog\AuditLog`, and log calls changed from `Log::create()` to `AuditLog::create()`. Event type strings and log levels are unchanged.
- **Framework Support**
    - Added Laravel v13.x support.
    - Removed support for the legacy Laravel v8, v9, and v10 releases.
        - **Why:** These versions are past their maintenance windows. Dropping them keeps the dependency matrix focused on supported framework releases.
    - The minimum PHP version is now `^8.2`. The supported Laravel range is `^11.0`, `^12.0`, and `^13.0`.
    - `nesbot/carbon` supports `^2.72.2 || ^3.0`.
- **Error Messages**
    - The `ConfigurationException` for missing credentials now lists every location that was checked and how to fix it, instead of reporting only "The JSON key contents are empty."
    - A base64 encoded `GOOGLE_APPLICATION_CREDENTIALS` value is detected and named as the problem.
    - A JSON key that cannot be parsed reports the JSON error and the source it came from.
    - A service account key missing `client_email`, `private_key`, or `private_key_id` names the missing keys instead of raising an undefined property error.
    - A `private_key` that OpenSSL cannot parse is reported as a configuration error, which most commonly means its newlines were not escaped as `\n`.
    - Requesting a scope that was not consented to during `gcloud auth application-default login` reports the scope and the exact command to grant it.
    - Expired `gcloud` credentials report that reauthentication is needed rather than surfacing Google's `invalid_rapt` string alone.
    - Setting `subject_email` with a credential type that cannot perform domain-wide delegation is rejected with an explanation instead of failing at Google.

### Upgrade Steps

- Update `composer.json` to require `boldlygrow/google-api-client:^5.0` and run `composer update`.
- Perform a find and replace across your code base from `Provisionesta\Google` to `BoldlyGrow\Google`.
- If you reference the audit logger directly, update `Provisionesta\Audit\Log` to `BoldlyGrow\AuditLog\AuditLog` (and `Log::create()` to `AuditLog::create()`).
- Ensure your application is running Laravel v11, v12, or v13 and PHP v8.2 or newer before upgrading. Applications on Laravel v8, v9, or v10 must upgrade the framework first, or stay on `boldlygrow/google-api-client:^4.0`.
- Re-publish or update the config file to pick up the new docblocks if desired: `php artisan vendor:publish --tag=google-api-client`.
- No functional change is required beyond the namespace and dependency updates. Your existing connection configuration, service account keys, and API calls continue to work.
- This is not an exhaustive list. Review the `README.md` for the latest syntax and usage guidelines.
